# Causal Architect — 背景と事件の因果構築

## 原則
人物の属性の箇条書きは背景ではない。「この過去が、この信念と制約を生み、この手段を選び、この被害と痕跡が発生した」までをつなぐ。神話的な法則は物語内部で首尾一貫させる。

## 最低限の因果鎖
1. **起点**：何が誰に起きたか。証言・物証・体験など接触可能な起点を明示。
2. **受け取り方**：当事者がそれをどう解釈したか。客観的事実とNPCの誤解を分ける。
3. **目的**：何を達成し、何を避けたいか。失敗を恐れる理由と優先順位。
4. **資源・制約**：知識・技能・財力・時間・身体条件・協力者・神話的代償は何か。
5. **選択**：複数の可能な行動のうち、なぜ今、その方法、その場所、その対象なのか。
6. **実行**：必要条件が実行より前に成立しているか。失敗した場合の反応は何か。
7. **結果と痕跡**：他者や環境がどう変わり、何が探索可能な情報として残るか。
8. **PCへの結節**：PCがこの因果鎖のどこを断ち切り、選び直し、明らかにできるか。

## 因果グラフの記法
`事実F1 -> 解釈B1 -> 動機M1 -> 取得K1 -> 制約R1 -> 行動A1 -> 痕跡E1`。
各矢印に「その結び付きの根拠」を1文添える。**NPCの視点で信じられること**と**KPから見た真実**は別列で管理する。

## 必須の5つのストレステスト
- 対象固有性：別人でもよいなら、なぜそのPC/NPCを選ぶのか。個人条件がなければ「偶然選ばれた」こと自体の現実的な選定過程を示す。
- 代替手段：暴力・殺人・儀式など極端な行動に、より簡単な代替案があるか。NPCが代替を知らなかった／誤解した場合、その理由を示す。
- 時間と順序：原因は結果より前か。逆因果や並行世界を使うなら、世界線ごとの情報・移動経路を明記。
- 資源と実行性：その手順に必要な能力・物品・協力者・費用をNPCが持つか。
- 失敗耐性：PCの妨害、予定外の証言、NPCの方針転換でも世界の反応が説明できるか。

## 背景の奥行きを作る
個人（トラウマ・欲求）／関係（恩義・対立）／社会制度（職務と制約）／神話（例外的法則）／探索（物証・噂・記録）をつなげる。描写を増やすだけでは合格しない。実際のセッションで参照されない説明を必要以上に増やさない。

## 無限後退と閉じ方
- 人間の行動や伝達経路は、説明を求められる重要点を閉じるまで追う。
- 神話的な究極原因は「意図的な不可知」とできる。ただし現在起きていることの**条件・範囲・例外**を固定し、物語上の判定可能性を損なわない。
- 連続修正しても再び同じ問題が出る場合、問題を移動しただけ。設定を足すのを止め、問題の元となる前提を組み替える。
- 確定設定を変えないと説明できない場合はその旨を明示してユーザーへ変更案を提示。

## 成果物
`assets/templates/causal-chain.md` の形式で「事実→行動→痕跡」と「各矢印の根拠」を記録。`adversarial-review.md` に従って検証し、重大な未説明因果が0件になるまで候補扱い。


## v1.6: PCへの結節は類型で検証する
1. `pc-involvement.md` で `direct_background` / `npc_mediated` / `hybrid` / `undetermined` を設定する。
2. 背景当事者型では、PCの過去・秘密・能力・行動と背景事件の間の**具体的な因果の矢印**を記す。PC不在時の結末比較や救済義務を課さない。
3. 外部介入型では、PC不在で自律的に進む事件の線（NPCの目標と行動による自然進行）を先に描き、PCとNPCの接触、その後どこで事実・行動・関係・結果が変わるかを比較する。変化の善悪は問わない。
4. 複合型では両方の評価を適用する。分類できない草案は未決定と記録し、完成時までに判定する。
5. 魔術師NPCの場合は `magician-psychology.md` の最上位目的と危険許容を加える。表面的に「怖かった／狂っていた」だけでは因果を閉じない。
